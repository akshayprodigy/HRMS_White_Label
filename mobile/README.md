# HRMS Mobile (white-label)

Expo development-build app (expo-router + TypeScript) for the HRMS backend.

- **Expo SDK 58** (`expo ~58.0.25`, released 2026-09-29), **React Native 0.88.1**, React 19.3.0, TypeScript 6 (strict)
- Not Expo Go: native modules (camera, background location, push) need a development build.

## Commands

```bash
npm install
npm run check          # eslint + tsc --noEmit + jest
npm run doctor
TENANT=dev npx expo start          # Metro (after a dev build is installed)
scripts/build-tenant.sh dev ios    # prebuild + run on a simulator (DEVICE="iPhone 15")
scripts/build-tenant.sh dev android
```

Jest runs with `--watchman=false` (a broken local watchman install otherwise aborts the run).

## White-label tenants

Each tenant lives in `tenants/<name>/`: `tenant.json`, `icon.png`, `splash.png`.
`app.config.ts` reads `TENANT` (default `dev`), validates `tenant.json` (fails fast listing every problem)
and maps it to name/slug/scheme/icons/splash/`ios.bundleIdentifier`/`android.package` and `extra.tenant`
(colors, `apiBaseUrl`, feature flags) which the app reads at runtime via `expo-constants`.
Validation is `tenants/validate.js` (plain CommonJS with a `.d.ts`) because Expo only transpiles `app.config.ts` itself.

Add a tenant: copy `tenants/acme`, edit `tenant.json`, replace the icon/splash (or run `npm run gen-assets -- <tenant>`
for colour placeholders), then `scripts/build-tenant.sh <tenant> <ios|android> [debug|release]`.

`ios/` and `android/` are generated by `expo prebuild` and gitignored.

### API base URL
`apiBaseUrl` is per tenant. On the Android emulator a `localhost`/`127.0.0.1` host is rewritten to `10.0.2.2`
(physical devices are left alone). The iOS simulator uses `localhost` directly.

### Release builds (EAS)
`scripts/build-tenant.sh <tenant> <ios|android> release` refuses tenants whose `apiBaseUrl` is localhost/10.0.2.2 or not https,
then runs `TENANT=<tenant> eas build --local --platform <p> --profile production` (the production profile has no
TENANT in `eas.json` on purpose; `app.config.ts` throws if a production EAS build has no `TENANT`).
Bump `buildNumber` (and `version`) in the tenant's `tenant.json` for every store upload; it feeds iOS `buildNumber` and Android `versionCode`.
Credentials that are not in this repo: an Apple team + signing (per bundle id), a Google Play upload key,
an EAS account/project per tenant, and push credentials (FCM service account, APNs key).
`eas.json` profiles: `development` (dev client, simulator), `preview` (internal), `production` (store).

## Layout
`app/` expo-router routes (`(auth)/login`, `(tabs)/{index,punch,leave,schedule,more}`) -
`src/api` axios client (bearer, single-flight 401 refresh, `ApiError`) - `src/auth` secure token storage + `useAuth` -
`src/theme` tenant-driven light/dark tokens - `src/components/ui.tsx` Screen/Text/Button/TextInput/Card -
`src/features/*` feature code - `tenants/` - `scripts/` - `__tests__/`.

## Navigation, gate and approvals (Task 6)
- Tabs: Home, Punch, Leave, Schedule, More, plus **Approvals** (hidden via `href: null` unless the user is an approver by
  role name (hr/pm/admin/super admin), an `*approv*`/`admin access` permission or superuser - from `/auth/me` - or the merged queue is non-empty;
  the queue check reuses the Approvals query and runs only once the attendance gate is open). Detail route: `app/approval/[key].tsx`.
- Attendance gate = backend `verify_attendance`: only **superusers** are exempt (an admin role is not). Gated routes: `/leave`, `/roster/*` (except
  running-late), `/approvals`, `/approval-chains`, `/dashboard`. Not gated: `/attendance/*`, `/broadcasts/my`, `/auth/me`. The gate 403 body is
  `{"error":{"code":"ATTENDANCE_REQUIRED",...}}`. `useAttendanceGate()` (query key `['attendance-today']`) drives the one-time redirect to Punch and the
  "Punch in to see this" notice. The hint (`/attendance/today`) is confirmed by the first gated call (`/dashboard/pending-count`); only a real `ATTENDANCE_REQUIRED` 403 sets `gated`. **Task 7 must invalidate `['attendance-today']` and `['pending-count']` after punching.** AppState drives react-query focus (`src/lib/appFocus.ts`); netinfo isn't installed, so onlineManager is not wired.
- Times from the API are UTC and are labelled "UTC" in the UI (`src/lib/time.ts`).

## Punch, selfie liveness and offline queue (Task 7)
- Code: `src/features/punch/` (`PunchScreen`, `SelfieCapture`, `PendingBanner`, `RunningLateCard`, `queue.ts`, `api.ts`, `liveness.ts`, `location.ts`, `store.ts`).
- Endpoints: `POST /attendance/mark` (mode `mobile`), `POST /attendance/punch-out`, `GET /attendance/today`, `POST /attendance/selfie` (multipart `file`, JPEG compressed under 3 MB), `POST /attendance/offline-sync`, `GET/POST/DELETE /roster/my/running-late`.
- Geofence: STRICT rejections are `422` with `detail:{error,message,...}`; `normalizeError` surfaces `message` and `code` (e.g. `OUTSIDE_GEOFENCE`). Flagged results (`geo_flag`/`attribution_flag`) show a review notice. After a punch we invalidate `['attendance-today']`, `['pending-count']`, `['roster-week']`.
- Offline: a punch is queued only on transport failure (status 0), 5xx or 429 (server did not judge it); every other 4xx is shown, never queued. The queue is one JSON file in `Paths.document` (expo-file-system; expo-sqlite is overkill for a handful of punches) plus selfie files copied to `document/selfies`. Sync runs on mount, app foreground, network regain (`expo-network`) and a 60s tick, with persisted exponential backoff (30s doubling, cap 15 min; manual "Sync now" and network regain bypass it). Selfie uploads first (`selfie_id` is stored so it is never re-uploaded), then `offline-sync`; `created`/`duplicate` leave the queue, `rejected` (terminal) moves to a list with the reason. A warning shows for items older than 10 h (server default window 12 h). Sync only runs while the app is alive (no background task yet).
- Liveness: real on-device face detection. `FaceCamera.tsx` (the only file importing the native modules, loaded lazily via `faceCameraLoader.ts`) runs `react-native-vision-camera` v5 (front camera, photo output) with `react-native-vision-camera-face-detector` (Google ML Kit; classification on for eye-open probabilities, fast mode, no landmarks/contours). Detector output goes through `faceSignal.ts` (`facesToObservation`: exactly 1 face = visible, 0 or >1 = not visible so a bystander/photo-in-frame cannot pass; throttled to ~12 observations/s, visibility changes never dropped) into a `FaceSignalSource`. `liveness.ts` stays pure: `ChallengeLivenessDetector` picks a random challenge per attempt (`blink`: eyes open -> closed -> open; `turn_head`: face centred (|yaw| < 10) then |yaw| >= 20 deg), waits up to 8 s, then takes the still with VisionCamera's photo API (HD 4:3, then the existing 720px/3 MB JPEG compression). Losing the face (or a second face appearing) mid-challenge resets progress. **Yaw sign decision:** ML Kit's yaw sign differs by platform and front-camera mirroring, so the head turn is sign-agnostic (either direction counts; only |yaw| is used) - no per-platform verification needed. Pass = `liveness_passed true`; timeout = `false`, which the backend flags for HR review. UX: a failed challenge shows a message and allows 2 retries; after that "Submit for HR review" sends the last still with `liveness_passed = false`. If the native modules cannot load, `SelfieCapture` falls back to the system camera (expo-image-picker, front) with `liveness_passed = null` (unknown, never `true`); `FallbackLivenessDetector` (2 frames, null) remains the default detector when no face source exists. Tenant flag `features.devLivenessBypass` (dev only) takes one frame with `liveness_passed = null`. This is a challenge-response check, not certified presentation-attack detection (a replayed video of the user could pass). Needs a physical device or an emulator with a webcam to verify real faces; there are no iOS simulator ML Kit arm64 slices, so test iOS on hardware.
- Mock location: Android only via expo-location `mocked`; iOS cannot report it (server treats the flag as untrusted).
- Permissions: `expo-location` (when-in-use string) and `expo-image-picker` (camera string, shared with the punch selfie; microphone off) plugins plus `android.permissions: [CAMERA]` in `app.config.ts`. vision-camera / face-detector / nitro modules ship no Expo config plugin (they autolink), and the permission is requested at runtime through VisionCamera's permission API (denied: explanation + Open Settings). A dev build is needed (not Expo Go).
